# Parking a selector and an executor

This experiment on the single collector at `777e9f76` adds one byte per dense stripe to hold a selected identity before its source bit clears. The byte and the stripe’s permanent group encode the exact ID. Staging runs outside the marking reader, domain cycle and coordinator locks. A peer can take the byte under the usual marking interlock, validate the exact live birth and reserve traversal. Strong closure seals the source words and then the transfer bytes. **The runtime change was withheld because the last executor still blocks reclamation.**

| Parked thread | Observed state | Peer outcome while parked |
|---|---|---|
| Selector, immediately after clearing the source bit | Transfer is public, child and grandchild are physically white, no marker reservation or marking reader, cycle and coordinator locks available | Old collection traces the child and grandchild, reclaims the idle-detached control, then a new full ticket reclaims the treatment. In a separate demand-only case, a capped allocation recovers within 2,048 polls with all initial headroom reserved and no external collection ticket. |
| Executor, after consuming the transfer and physically marking the child | Marking reader held, child marked, grandchild white, zero in-flight reservations | Both the full ticket and allocation remain pending after 2,048 peer polls and steps under each publication policy. Resuming the executor lets collection finish. |

The selector schedule ran in 48 randomized fresh native processes, split between the default and experimental identity indexes. Each covered both publication policies, coordinated and independent marking, and separate full-ticket and demand-only cases. Another 24 processes stopped the last independent executor under each publication policy. The native GC library passed 662 tests. WASIp2 passed the four applicable GC tests and both targets passed strict Clippy. The WASI tests exercise the cooperative path. The forced thread suspension is a native test.

Antigravity identified a repeated-ID ordering hazard. A delayed selector can clear a fresh source bit for the same ID after another helper consumes the transfer. For this experiment the byte represents one strong retention obligation per exact ID in a single old epoch. Consuming that transfer gives the executor this obligation under marking admission. Re-arming the bit does not encode a second independent callback. A regression re-offers the first ID and an adjacent sibling between transfer and source clearing, then seals the source before taking the sibling. The sibling is still discovered and closure completes. Any use for dirty rescans or independent per-update work would require additional state. The remaining JVM integration question is how peers can complete outstanding traversal after the physical mark without executing an arbitrary callback twice.
